## 0. Big picture: what changed from the old App.jsx

**The v4.8 data model is a different model, not an extension of the old one.** The following old concepts appear nowhere in the v4.8 app code (confirmed by grep): `arrayCount`, `arrayOffset`, `overrides`, `rippleOffsets`, `childIndex`, `empId`, `employees`, `y`, and task-level `status` (`todo/progress/done/late`). The Shift+drag "ripple" feature is gone.

| Old (App.jsx) | v4.8 |
|---|---|
| `employees` ("Phases") with tailwind `color` class | `projects` with hex `color`, `deadline`, `archived`, `notes` |
| Free vertical `y` (px, snapped to 52) | Rows are **steps** inside **groups**; a task has `stepId` |
| Array/children/overrides/ripple | Removed. Duplication is done by Alt+drag, copy/paste, or Duplicate |
| Task `status` | Removed. Per-task `subtasks[]` each have their own `status` and are shown on a Kanban board |
| Epoch = today at midnight | Fixed epoch `new Date(2026,4,1)` (local time, 1 May 2026) |
| Shift+wheel zoom | **Plain wheel** zooms, with smoothing. Shift is not needed |
| Read-only gist raw fetch, copy JSON | GitHub Gist API read and PATCH, token, conflict check, verify loop, undo/redo, multi-select, marquee, copy/paste |
| — | Collapsible groups, drag-reorder of groups and steps, context menus, deadlines lane, weekend shading |

## 1. Data model

### 1.1 Gist file (exact shape written by upload `un` and by export `_n`)

```json
{
  "projects": [ /* Project[] */ ],
  "groups":   [ /* Group[] (each contains steps) */ ],
  "tasks":    [ /* Task[] */ ],
  "lastEditedBy": "Alice",
  "exportedAt": "2026-11-16T14:03:22.511Z",
  "version": "4.8"
}
```

Key order is literally `projects, groups, tasks, lastEditedBy, exportedAt, version`. The file is serialized with `JSON.stringify(payload, null, 2)` and stored as the content of gist file `data.json`.

| Field | Type | Meaning |
|---|---|---|
| `projects` | Project[] | Clients/productions; supply each block's colour; have deadlines |
| `groups` | Group[] | Ordered categories ("phases"), each holding ordered `steps` (the timeline rows) |
| `tasks` | Task[] | Timeline blocks |
| `lastEditedBy` | string | `username || "Anonymous User"` (username comes from localStorage `moc_username`) |
| `exportedAt` | ISO-8601 string | `new Date().toISOString()` at upload/export time. Used for conflict detection and to verify a write |
| `version` | string | Hard-coded `"4.8"`. **Written but never read**; no migration branches on it |

### 1.2 Project

```json
{ "id": "p1", "name": "Alpha Commercial", "color": "#FFD166", "deadline": 14, "archived": false, "notes": "" }
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Seed values `p1..p3`; new ones are `` `p_${Date.now()}` `` |
| `name` | string | Display name. The UI shows `"Unnamed"` when empty |
| `color` | string | Hex colour (`#RRGGBB`) taken from `<input type=color>`. A legacy Tailwind class `bg-[#xxxxxx]` is also accepted (see `Ye` in 1.6) |
| `deadline` | integer \| null | A day offset from the epoch (inclusive deadline day). `null` means no deadline. The deadline line is drawn at the **end** of that day (`Hn(deadline)+dayWidth`) |
| `archived` | boolean | Archived projects are hidden from the main Projects list but **still render their tasks and deadline flags** |
| `notes` | string | Free text ("Add links, descriptions, or details...") |

A new project is created as `{id:`p_${Date.now()}`, name:"New Project", color:"#FFD166", deadline:null, archived:false, notes:""}`.

### 1.3 Group and Step

```json
{ "id": "g1", "name": "Phase 1: Pre-Production",
  "steps": [ { "id": "s1", "name": "Pre-Production" }, { "id": "s2", "name": "Scripting" } ] }
```

| Field | Type | Meaning |
|---|---|---|
| `group.id` | string | Seed `g1..g3`; new `` `g_${Date.now()}` ``; legacy `g_legacy` |
| `group.name` | string | Category header text. New default `"New Category"` |
| `group.steps` | Step[] | Ordered rows |
| `step.id` | string | Seed `s1..s6`; new `` `s_${Date.now()}` ``; group-duplicate gives `` `s_${Date.now()}_${i}` `` |
| `step.name` | string | Row label. New default `"New Step"` |

There is no separate step list: steps exist only inside groups. Collapsed state is **not** stored in the data; it lives in localStorage (see 2.4).

### 1.4 Task (timeline block)

```json
{ "id": "t1", "projectId": "p1", "stepId": "s2", "start": -2, "duration": 5,
  "title": "Draft 1", "notes": "",
  "subtasks": [ { "id": "st1", "title": "Write outline", "status": "done" } ] }
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `` `t_${Date.now()}` `` (create/duplicate) or `` `t_${Date.now()}_${i}` `` (paste/Alt-duplicate) |
| `projectId` | string \| null | The owning project. A new block gets `projects[0].id` (even if that project is archived), or `null` when there are no projects |
| `stepId` | string | The row it sits on |
| `start` | integer | Day offset from the epoch (day 0 = 2026-05-01). Always an integer in practice (floor/round everywhere) |
| `duration` | integer ≥ 1 | Length in days. End date shown = `start + duration - 1` (inclusive) |
| `title` | string | A new block from double-click starts as `""`; seed tasks have titles |
| `notes` | string | Block notes |
| `subtasks` | Subtask[] | Kanban cards. May be missing on old data (code uses `t.subtasks||[]`) |

A task is an **orphan** when `projectId` is not among `projects` **or** `stepId` is not in any group's steps. Orphans with a bad `stepId` are not rendered. Orphans with a bad `projectId` but valid step are rendered as "No Project" in `#666666`. The empty Inspector shows a "Clear N Orphans" button.

### 1.5 Subtask

```json
{ "id": "st3", "title": "Lighting setup", "status": "progress" }
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `` `st_${Date.now()}` ``, or `` `st_${Date.now()}_${i}` `` / `` `st_${Date.now()}_${t}_${n}` `` when copied |
| `title` | string | Card text (multi-line allowed; Shift+Enter inserts a newline) |
| `status` | `"todo"` \| `"progress"` \| `"done"` | Kanban column |
| `isCompleted` | boolean (legacy, read-only) | Back-compat: when `status` is missing, `isCompleted` true means done and anything else means todo. Never written |

Order within `subtasks` is meaningful. After any Kanban drop the array is rebuilt as `[...todo, ...progress, ...done]`.

### 1.6 Migration / back-compat code actually present

1. **`steps` → `groups`** (in load `gn`): `let u=t.groups; if(!u&&t.steps) u=[{id:"g_legacy",name:"Main Timeline",steps:t.steps}]`. The result is applied both on initial load and on a manual refresh.
2. **Colour class → hex** (`Ye`): `e ? (e.startsWith("bg-[") ? e.match(/\[(.*?)\]/)?.[1] || "#666666" : e) : "#666666"`. This is applied wherever a project colour is rendered.
3. **Subtask `isCompleted`**: handled as described in 1.5 (Kanban filters, progress counts).
4. **Not migrated** [inferred consequence]: the original App.jsx format (`employees`, tasks with `empId/y/arrayCount/...`). Loading it would set `tasks` raw. `projects` and `groups` are missing, so the seed defaults stay. Every task then lacks `stepId`/`projectId`, so they become invisible orphans. `employees` is ignored. Array children are lost.
5. On load, each of `projects`, `groups`, `tasks` is applied **only if present** (`t.projects&&r(t.projects)`, and so on). A missing key keeps the current/default value.

### 2.2 Zoom-dependent display thresholds

- Ruler interval: `zoom<=0.03` → `year`; `<=0.15` → `month`; `<=0.6` → `week`; otherwise `day`.
- Weekend hatch shading: only when `zoom>0.15`.
- Weekday sub-label (`MON`…) in day ticks: only when `dayWidth>48` (zoom > 1.2).
- Deadline flag shows the project name: only when `zoom>0.4`.
- Task text (title + project name) is rendered only when block width `>40` px. Below that there is no inline-edit input either.

## 3. Features and interactions

### 3.1 Canvas navigation
- **Zoom: plain mouse wheel** (any wheel event, vertical or horizontal; no modifier needed) over the timeline container. The handler is non-passive and always calls `preventDefault`, so the **wheel never scrolls the canvas vertically**. Each event multiplies the *target* zoom by 0.85 or 1.15, clamped to [0.01, 3]. A requestAnimationFrame loop lerps the current zoom toward the target (factor 0.25) while keeping the date under the mouse fixed: `timeAtMouse=(scrollLeft+mouseX)/currentZoom`, `newScrollLeft=timeAtMouse*zoom-mouseX`, applied in a `useLayoutEffect` on zoom change. Wheel events are ignored while panning.
- **Pan:** middle mouse button drag, or **Alt + left drag**, anywhere on the timeline container *except* on elements marked `data-no-pan="true"` (task blocks and deadline flags) for the left button. The middle button pans even over blocks. Panning moves `scrollLeft`/`scrollTop`, cancels any zoom animation, and sets `body.cursor='grabbing'`. `auxclick` with the middle button is `preventDefault`ed.
- **Vertical scrolling:** the canvas scrollbar, panning, or the **wheel over the left sidebar** (sidebar `onWheel` adds `deltaY` to the canvas `scrollTop`).
- The ruler (horizontal) and left sidebar (vertical) are synced from the canvas `onScroll`. Viewport state is updated via rAF throttling.
- **Initial scroll** (on mount): the canvas is centred on this week's Monday + 3.5 days, at the current time of day (`(CENTER_DAY + (now-EPOCH)/day + (-(daysSinceMonday)+3.5)) * 40 * zoom - clientWidth/2`). A ResizeObserver tracks the width.
- **Now marker:** a red 2 px line with a glow in the ruler (with a triangle) and the canvas, at `(CENTER_DAY + (Date.now()-EPOCH)/864e5)*40*zoom`. Refreshes every 60 s.

### 3.2 Selection
- `selectedTaskIds: string[]` (`g`).
- **Click a block:** if it is not selected, selection becomes `[id]`. If it is already selected (part of a multi-selection), the selection is kept, so you can drag the whole group. Clicking does not collapse a multi-selection to one block. The Inspector tab activates.
- **Shift+click a block:** toggles membership. If that removed it, there is no drag.
- **Marquee:** left-press on empty canvas (not Alt, not middle button). The press blurs the focused element. Without Shift the selection is cleared immediately (so a plain click on empty canvas deselects). **Shift+marquee is additive** to the selection at press time. A live rectangle (`bg-[#118AB2]/20`, border `#118AB2`) is drawn. A task is hit if its horizontal span overlaps and its **full step row** (68 px, not the 56 px block) overlaps. Tasks on hidden (collapsed) steps are skipped. If the selection becomes non-empty, the Inspector tab opens. The rectangle uses canvas-local coordinates captured at mousedown.
- Deleting tasks removes them from the selection (`Fn` filters; Delete key and bulk delete clear it).

### 3.3 Creating blocks
- **Double-click empty canvas** (the target must be the canvas itself, below the 44 px deadline lane, on a **step** row, not a group header). It creates `{id, projectId: projects[0]?.id ?? null, stepId: row.id, start: Math.floor(pxToDay(x)), duration: 5, title: "", notes: "", subtasks: []}`, selects it, opens the Inspector, and starts inline title editing (`ee(id)`). **No undo snapshot is taken** (see Bugs).

### 3.4 Moving blocks (`Qn`)
- Left-press on a block, with a 3 px threshold before the drag starts. All selected blocks move together.
- Horizontal: `days = round(pxToDay(anchor.initialLeft + dx)) - anchor.start` (snapped to whole days).
- Vertical: the anchor snaps to the **visible step** whose row centre is nearest the pointer. `stepOffset` is clamped so every dragged block stays inside the visible-steps list (blocks keep their relative row distances). Rows in collapsed groups are skipped, since moves index into `visibleSteps`.
- During the drag the DOM elements follow the raw pointer (`opacity .7`, `z-index 100`, `pointer-events:none`). `#task-drop-indicator` (dashed green box) shows the **anchor's** snapped landing slot only.
- On release: if days≠0 or stepOffset≠0, take an undo snapshot (unless Alt) and apply `start+=days` and `stepId = visibleSteps[idx+stepOffset].id` to every dragged block. Otherwise styles are reset.
- **Alt+drag a block = duplicate:** takes an undo snapshot immediately and clones every selected block (new ids `t_${now}_${i}`, subtask ids `st_${now}_${i}_${j}`, same title, no "(Copy)" suffix). The selection becomes the clones and the clones are dragged; the originals stay.

### 3.5 Resizing (`$n` right edge, `er` left edge)
- 10 px (`w-2.5`) handles on each edge; hover shows `bg-white/30` and the cursor is `ew-resize`.
- Without Shift: if the block is in the selection, **all selected blocks** are resized by the same day delta (right: `duration+=c`; left: `start+=c, duration-=c`). Otherwise the selection becomes `[id]`. The delta is clamped so every duration stays ≥ 1.
- **Shift+drag edge = linked adjacent ("rolling") resize:** the selection is forced to `[id]`. Right edge: finds a task in the same step whose `start === this.start+this.duration` (exactly abutting on the right) and shifts its start by `c` while shrinking or growing it (`start+=c, duration-=c`). Left edge: finds a task in the same step whose `start+duration === this.start` and changes its `duration+=c`. Both sides are clamped to ≥ 1 day.
- One undo snapshot is taken on release if c≠0. DOM width/left is updated live during the drag.

### 3.6 Inline editing
- **Block title:** double-click the title/label area of a block (only rendered when width > 40 px) or use context menu → Rename. An `autoFocus` input. **Enter** blurs. On blur, the value is trimmed; if changed, take a snapshot and set it.
- **Group/step names:** always-editable inputs in the left sidebar (`id="input-${id}"`). Snapshot on focus, live update on change.
- **Subtask titles:** double-click a card or context menu → Rename. A textarea; **Enter** commits, **Shift+Enter** adds a newline. On blur, an empty trimmed value **deletes** the subtask.

### 3.7 Keyboard shortcuts (window `keydown`; ignored when focus is in an `input`/`textarea`)
The modifier is `metaKey` when `navigator.platform` contains "MAC", otherwise `ctrlKey`.

| Keys | Action |
|---|---|
| Ctrl/Cmd+C | `preventDefault` always. If there is a selection, copies the selected task objects into an in-memory clipboard (`$t` ref). The system clipboard is not used |
| Ctrl/Cmd+V | If the clipboard is non-empty: undo snapshot (deduped), clear future, then paste clones with new ids. They keep the same `stepId` and are shifted by `floor(mouseX/(40*zoom) - 3650) - min(clipboard.start)`, so the **earliest pasted block lands at the day under the last mouse position over the canvas**. If the mouse never moved over the canvas the shift is +1 day. The pasted blocks become the selection |
| Ctrl/Cmd+Z | Undo |
| Ctrl/Cmd+Shift+Z | Redo. There is **no Ctrl+Y** |
| Delete / Backspace | If there is a selection: snapshot (deduped), clear future, delete the selected tasks, clear the selection |
| Escape | Not handled anywhere |

### 3.8 Context menus (`A` state; fixed-position, 160 px wide, `z-[200]`; closed by any click on the app root)
Right-clicking one of these opens the menu:
- **Group header row** (sidebar): Rename (focuses `input-${id}`) · Duplicate · **+ Add Step** · — · Delete
- **Step row** (sidebar): Rename · Duplicate · — · Delete
- **Task block**: Rename (inline title edit) · Duplicate · — · Delete
- **Subtask card**: Rename · Duplicate · — · Delete

What each action does:
- Duplicate group (`Nn`): inserted right after the original, named `"${name} (Copy)"`, with new ids for its steps (`s_${now}_${i}`). **Tasks are not copied.**
- Duplicate step: inserted after the original as `"${name} (Copy)"` with a new id.
- Duplicate task (`Pn`): appended to the end of `tasks` with the same start and step, title `"${title} (Copy)"`, new subtask ids. It is not selected and sits exactly on top of the original.
- Duplicate subtask (`Bn`): inserted after the original as `"${title} (Copy)"`. It keeps its status.
- Delete group or step: **no confirmation**. Tasks on the deleted steps become orphans.
- All of these take an undo snapshot first.

### 3.9 Left panel: "Process Timeline" (220 px; toggled by the header button)
- Header bar: label "Process Timeline" and a green **+** button ("New Category"), which adds `{id:g_${now}, name:"New Category", steps:[]}`.
- The top 44 px lane is labelled "Deadlines" (party-popper icon).
- Group rows (36 px, `#161616`): grip handle (grip-vertical), chevron to collapse/expand (collapsed state is persisted to `moc_collapsed_groups`), and the name input in purple uppercase.
- Step rows (68 px, indented): grip handle and name input.
- **Reordering by drag (HTML5 DnD):** a row is `draggable` only while its grip is hovered (`vt` = hovered grip id). The drop position is the top or bottom half of the target row. Drop rules (`On`):
  - group onto group → reorder before/after.
  - group onto step → treated as "after that step's group".
  - step onto step → insert before/after the target step, **across groups allowed**.
  - step onto group header → insert as the **first** step of that group.
  - Dropping onto itself does nothing. One undo snapshot is taken per drop.
  - Indicator: a 3 px line, green `#06D6A0` for groups and blue `#118AB2` for steps. For group drops onto "bottom" it is drawn after the group's last visible row.
- Add Step (context menu) appends `{id:s_${now}, name:"New Step"}` and auto-expands the group if it was collapsed.
- Collapsing a group hides its step rows in both sidebar and canvas, and hides its tasks. No summary bar is shown.

### 3.10 Canvas rendering
- Ruler (32 px tall). Tick labels:
  - year: `"2027"`
  - month: `"JAN '27"`
  - week: Monday-aligned, `"JAN 4"`
  - day: date number, `"JAN 1"` on the 1st, plus weekday sub-label when wide
  - `isMajor` is true for every year/month/week tick, and for day ticks only on the 1st.
- **At day zoom, weekday (Mon–Fri) ruler cells are filled `#e8e8e8` with dark text and are one day wide; weekend cells stay dark.** **[inferred]** This may be intentional ("working days highlighted") or an inverted flag. Reproduce it as-is unless told otherwise.
- Grid: one vertical line per tick (opacity 1 for major, 0.4 for minor) and horizontal row lines. Group rows get a `bg-[#161616]/30` band. The area below the last row is darkened.
- **Weekend shading** (zoom > 0.15): each Saturday/Sunday column gets `rgba(255,255,255,0.03)` plus a 45° stripe pattern.
- **Deadline lane:** for every project (including archived ones) with a non-null numeric `deadline`, a 2 px vertical line in the project colour at the end of the deadline day (opacity .8), with a flag pill at the top (party-popper icon plus name when zoom > .4).
  - **Dragging the flag** (left button, not Alt) switches the right panel to the Projects tab and moves the line, snapped to days. On release, if the day changed, take a snapshot and set `deadline`.
  - Clicking the flag does not expand that project's card.
- **Task block:** background = project colour (`Ye`).
  - Selected: white border, `ring-2 ring-white`, z-40.
  - Title (semibold 11 px) with the project name below it (9 px, 70% opacity).
  - If there are subtasks: a 3 px progress bar along the bottom (`done/total`) and a `"d/u"` counter at the bottom right.
  - If there are notes: a text-align-start icon at the bottom right.
  - Minimum width 4 px.
- **Virtualization:** only tasks within ±4000 px of the viewport and on visible steps are rendered (`lr`).

### 3.11 Subtask Kanban (bottom drawer over the canvas column; only when exactly one block is selected)
- No subtasks: a 48 px bar "No Sub-Tasks / {title}" with "+ Sub Task" on the right. Clicking anywhere on it adds a subtask.
- Otherwise: a 40 px header "Sub-Tasks / {title}" with a badge "{done} / {total} DONE" and a chevron. Clicking toggles expanded (340 px) or collapsed. The expanded state is session-only (`ut`, default true; adding a subtask forces it open).
- Three columns, **To Do / In Progress / Done**, each with a count. Cards use HTML5 DnD with a custom drag image (a clone rotated 4°). A dashed green "ghost" placeholder shows the drop slot (top/bottom half of the hovered card, or the end of the column). On drop: snapshot, remove the card from its source column, set `status` to the target column, insert at the index (adjusted when moving down in the same column), and rebuild the array as todo+progress+done.
- Adding (`Rn`; from the "+ Sub Task" button at the bottom of To Do or from the empty bar): appends `{id:st_${now}, title:"", status:"todo"}` and immediately opens its editor. **No snapshot** is taken, but blurring with an empty title deletes it.

## 5. Sync flow (GitHub Gist)

State: `uploadStatus` (`M`) ∈ `idle | checking | confirming | confirming_conflict | uploading | verifying | success | failed`; `refreshStatus` (`It`) ∈ `idle | checking | uptodate`; `lastSyncedJson` (`u`, a string baseline); `lastSyncedExportedAt` (`Rt`); `pendingRemote` (`Bt`); `conflictRemote` (`Pt`); `token` (`wt`); `hasToken` (`Et`); `showTokenModal` (`Dt`); `tokenInput` (`kt`); `tokenError` (`jt`).

**Dirty flag** `hasUnsyncedChanges` (`tn`) = `lastSyncedJson ? JSON.stringify({projects,groups,tasks}) !== lastSyncedJson : false`.

### 5.1 Load (`gn(isManual=false)`, called once on mount and by the Refresh button with `true`)
1. If manual, set `refreshStatus='checking'`.
2. **If a token is in localStorage:** `GET https://api.github.com/gists/${GIST_ID}?t=${Date.now()}` with headers `Authorization: Bearer <token>` and `Accept: application/vnd.github+json`.
   - 401/403: delete the token from localStorage and state, set `hasToken=false`, throw.
   - Other non-OK: throw.
   - OK: `data = JSON.parse(json.files["data.json"].content)`.
   - Any failure logs `console.warn("Authenticated fetch failed, falling back to public fetch.")`.
3. **If not loaded yet:** unauthenticated `GET` of the same API URL (with cache-buster, `Accept` only). On non-OK, throw "Rate limit hit", which falls back to a **raw URL** fetch: `GIST_RAW_URL` (+`?t=now` **only when manual**) `.json()`.
4. Migrate `steps → groups` (1.6).
5. **Manual refresh:** if `JSON.stringify({projects,groups,tasks})` of the remote equals that of the **current local state**, set `uptodate` for 2 s and return. Otherwise set `pendingRemote = {...remote, groups}` and `refreshStatus='idle'`, which shows the "SYNC FROM GIST" modal.
   - "Yes, Override Local" (`vn`): **takes an undo snapshot (so it is undoable)**, applies the projects/groups/tasks that are present, sets `lastSyncedExportedAt = remote.exportedAt` and `lastSyncedJson = JSON({projects,groups,tasks})` of the remote, and closes the modal.
   - "No, Keep My View": closes the modal. The baseline is unchanged.
6. **Initial load:** applies the projects/groups/tasks that are present, sets `lastSyncedExportedAt = remote.exportedAt || now`, and sets `lastSyncedJson` = the remote JSON. The undo history is not touched.
7. Any thrown error: manual sets `refreshStatus='idle'` (no message). Initial load fails silently, leaving the seed data and `lastSyncedJson=''`.

### 5.2 Token entry / removal
- **Verify & Connect** (`sn`):
  - Clears the error.
  - Empty input gives "Please enter a token."
  - Otherwise `GET /gists/${GIST_ID}` with `Authorization: Bearer`. If OK: save `moc_github_token`, set token state, `hasToken=true`, close the modal, clear the input.
  - Non-OK gives "Invalid token or missing gist permissions."; an exception gives "Network error checking token."
  - **[inferred]** A GET only proves the token is valid. It does not prove it has `gist` write scope, so a read-only token passes here and fails later on PATCH.
- **Remove Device Token** (`cn`): removes it from localStorage, clears state, closes the modal.
- Opening via the lock-open icon pre-fills the input with the current token.

### 5.3 Upload click (`ln`); only possible when `hasToken && hasUnsyncedChanges && uploadStatus==='idle'`
1. `uploadStatus='checking'`.
2. `GET /gists/${GIST_ID}?t=now` with Bearer. Parse `files["data.json"].content`. `response.ok` is not checked.
3. If `remote.exportedAt && lastSyncedExportedAt && Date(remote.exportedAt) > Date(lastSyncedExportedAt)`, store `conflictRemote=remote` and set `confirming_conflict` (the CLOUD CONFLICT modal). Otherwise set `confirming` (the CONFIRM CLOUD PUSH modal).
4. **Any exception sets `confirming`**, meaning the conflict check is skipped.
5. Cancel in either modal sets `idle`.

### 5.4 Upload (`un`; from "Yes, Push to Cloud" or "I Know, Overwrite It")
1. Requires `hasToken && token`. Set `uploadStatus='uploading'`.
2. Build the payload `{projects,groups,tasks,lastEditedBy,exportedAt:new Date().toISOString(),version:"4.8"}` from the state at click time.
3. `PATCH https://api.github.com/gists/${GIST_ID}` with headers `Authorization: Bearer`, `Accept: application/vnd.github+json`, `Content-Type: application/json`, and body `{"files":{"data.json":{"content":<pretty JSON>}}}`.
4. Non-OK response:
   - 401/403/404: `hasToken=false`, delete the token, `tokenError="Token expired or unauthorized. Please re-enter."`, `uploadStatus='idle'`, open the token modal, return.
   - Other status: throw `Upload failed with status: N`, which leads to `failed`.
5. **Verify loop:** `uploadStatus='verifying'`. Until 30 s have elapsed: wait 3 s, then `GET /gists/${id}?t=now` (Bearer). If OK and the parsed `exportedAt === payload.exportedAt`, it is verified; break. Per-iteration errors are swallowed.
6. Verified: `success`, `lastSyncedExportedAt=payload.exportedAt`, `lastSyncedJson=JSON({projects,groups,tasks})` (the click-time state), then `idle` after 3 s.
7. Not verified after 30 s: `failed`, then `idle` after 5 s. Any thrown error: `failed`, then `idle` after 5 s.

Upload button appearance per state:

| State | Look | Icon / label |
|---|---|---|
| not dirty & idle | grey, `cursor-default`, disabled | check / "Up to date" |
| dirty & idle/confirming* | green tint | cloud-upload / "Upload Changes" |
| checking | green 20%, `cursor-wait` | spinning refresh / "Checking..." |
| uploading | same | bouncing cloud-upload / "Pushing..." |
| verifying | same | spinning refresh / "Verifying..." |
| success | solid green | circle-check-big / "Verified!" |
| failed | red tint | triangle-alert / "Upload Failed" |

The button is `disabled` whenever `uploadStatus!=='idle'` or the timeline is not dirty. Labels are hidden below `sm`.

## 6. Undo / redo mechanics

- `past` (`f`) and `future` (`m`) are arrays of snapshots `{projects, groups, tasks}` (the full arrays, shared by reference rather than deep-cloned; safe because all updates are immutable). They are **not** persisted and **not** synced.
- **Not included in a snapshot:** selection, zoom, scroll, collapsed groups, username, token, panel visibility.
- `snapshot()` (`N`) is called **before** a mutation. It pushes the current state to `past` unless it is JSON-identical to the last entry (dedupe), trims to the **last 50**, and **clears `future`**.
- Undo: pop the last `past` entry, push the current state to the **front** of `future`, apply it. Redo: take `future[0]`, push the current state to `past`, apply it. The header buttons use closure state; the keyboard path reads a `pn` ref (latest-state mirror updated every render) so the global listener is registered once.
- Undo/redo do not touch `selectedTaskIds`. A selection may keep pointing at ids that no longer exist; the Inspector then shows the empty state for 1 id because `F` is null.
- Operations that snapshot: move, Alt-duplicate (at press), resize, deadline drag, delete key, paste, context menu actions, group/step/subtask DnD, project add/archive/restore/delete, project deadline/colour/notes/name, inspector edits (on focus for text, per change for buttons and dates), bulk edits, clear orphans, accepting a remote ("Override Local"), inline title commit, subtask edit commit.
- Operations that **do not** snapshot: **double-click create**, **add subtask** (`Rn`), collapse/expand, and the initial load.

## 7. Bugs and rough edges

1. **DST off-by-one in date display (known).** `offsetToDateString` (`Wn`) does `new Date(EPOCH.getTime()+n*864e5)`. The epoch is local midnight on 1 May (summer time in northern-hemisphere zones), so for any date in standard time (roughly Nov–Mar) the result is 23:00 of the previous day, and **the date shown in inputs is one day early**. The reverse function (`Gn`) uses `Math.round` and is correct, so the deadline and start/end date pickers show the wrong day for winter dates, and the end date is effectively shifted. It does not affect southern-hemisphere zones (reversed) or zones without DST. The now-marker and initial scroll are also off by 1 hour in winter (they divide raw ms by 864e5). The ruler and weekend shading use `setDate`/`Math.round` and are correct. Fix: `new Date(2026, 4, 1 + n)`.
2. **No local persistence.** Data lives only in memory and the Gist. A reload or closed tab loses all unsynced edits. There is no `beforeunload` warning. In read-only mode (no token) every edit is lost on reload.
3. **"Read Only" is cosmetic.** Without a token the user can still edit everything; only uploading is blocked.
4. **Upload permanently disabled if the initial load failed.** The dirty flag is `false` while `lastSyncedJson===''`, so after a failed startup fetch (offline, rate-limited and raw also failing) the Upload button stays "Up to date" until a successful Refresh is accepted. If the remote is identical, Refresh only says "Up to Date" and still does not set the baseline.
5. **Refresh compares the remote against current local state, not the baseline.** With unsynced local edits and an unchanged remote, it still offers "Override Local", and accepting it discards the edits (recoverable via undo). It cannot tell "remote changed" from "I changed".
6. **Conflict detection is timestamp-only and fragile.**
   - `exportedAt` comes from the *other client's* clock, so clock skew can cause false or missed conflicts.
   - When `ln`'s fetch fails, the conflict check is skipped silently.
   - When an upload's PATCH succeeded but verification timed out (`failed`), `lastSyncedExportedAt` is not updated, so the next upload reports a "conflict" with the user's own data.
   - The initial load may come from the CDN-cached raw URL with **no cache-buster** (stale for minutes) **[inferred: gist raw caching]**, which also feeds stale baselines.
7. **Verify-loop / edit race:** on success the baseline is the click-time state. That is correct, but edits made during the up-to-30 s verify are not part of the upload, and the button stays disabled during that window.
8. **The token check doesn't verify write scope** (5.2). A bad token is only discovered on PATCH, which then deletes it.
9. **Controls & Shortcuts modal is dead code.** There is no setter call with `true`, so nothing opens it. Wire it to a "?" button in the rewrite.
10. **Missing undo snapshots:** double-click create and add subtask. Undoing right after either reverts two operations at once (the creation plus the previous one), because `past` holds the state from before the previous action.
11. **Focusing any text input clears the redo stack** (`onFocus:N` calls `h([])` even if nothing changes). Date-input changes snapshot on every change event.
12. **Alt-duplicate with no or zero-delta movement** leaves the clones stacked exactly on the originals (a snapshot was already taken). Context-menu Duplicate of a task also stacks the copy on the original.
13. **Rename via context menu does nothing for narrow blocks** (≤40 px wide), because the inline input isn't rendered. The same applies to the auto-edit after double-click creation when zoomed out.
14. **Wheel always zooms.** There is no wheel vertical scroll on the canvas, and trackpad two-finger scrolling zooms. Vertical navigation requires the scrollbar, pan, or the wheel over the sidebar.
15. **Archived projects** still render their blocks and deadline flags, and appear in the Inspector/Bulk "Assign Project" lists. New double-click blocks use `projects[0]` even if it is archived.
16. **Deleting a project, group or step has no confirmation** and silently orphans its tasks. Orphans on a missing step are invisible until "Clear N Orphans" (shown only with nothing selected).
17. **Ctrl/Cmd+C always `preventDefault`s** outside inputs, which blocks copying page text. The clipboard is internal only (not cross-tab). Paste goes to the same rows even if those steps were deleted, producing orphans.
18. **Escape** does nothing (does not close modals or menus, does not clear selection). The context menu closes only on a click.
19. **IDs from `Date.now()`** can collide when two creations happen in the same millisecond (e.g. a duplicate group's `s_${now}_${i}` vs a step `s_${now}`). They are also not globally unique across users editing concurrently.
20. **Bulk "Set Title for All"** is an uncontrolled input. It overwrites all titles on the first keystroke and shows nothing on re-open.
21. **Shift+edge resize** forces a single selection (it drops an existing multi-selection).
22. **Gist API `truncated` content** (files > 1 MB) is not handled **[inferred risk]**. `response.ok` is also not checked in `ln`.
23. **Ruler weekday cells highlighted (white) rather than weekends** at day zoom. This might be intended; flagging it.
24. `Xt` (zoomRef) is written but never read (dead). The `version` field is written but never read.
25. **Legacy App.jsx data is not migrated** (1.6 item 4). Loading an old gist hides all tasks as orphans.
26. Marquee coordinates use the canvas rect captured at mousedown, so scrolling during a marquee (pan is impossible mid-marquee, but the scrollbar is not) gives a mismatched rectangle. Minor.
